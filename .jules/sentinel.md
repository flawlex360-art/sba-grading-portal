## 2026-08-05 - Missing Role-Based Access Control on Institutions and Archives Collections
**Vulnerability:** The Firestore Security Rules (`firestore.rules`) completely lacked match rules and authorization controls for the critical `institutions` and `archives` collections. By default, either access to these collections was completely restricted (breaking the application features for legitimate administrative users) or permissive, potentially exposing sensitive tenant records, multi-tenant definitions, and archived student grades to unauthorized client-side access. Furthermore, there was no matching backend logic in firestore rules to authorize the "Senior Super User" role (`system@flawlex.com`).
**Learning:** Security rules were only configured for basic collections (`teachers` and `schools`). In direct client-to-database architectures like Firebase Firestore, any collection used by the client-side code must be explicitly defined and secured in the server-side rules. Forgetting to lock down secondary or archive collections creates an immediate high-severity bypass vectors.
**Prevention:** Always maintain a checklist of all database collections referenced in frontend queries (e.g. `institutions`, `archives`). Enforce robust multi-tenant constraints on all collections using helper checks like `isSeniorSuperUser()` and matching `institutionId` parameters across user profile documents.
